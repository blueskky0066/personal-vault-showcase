# Personal Vault · 个人多媒体资源库

Personal Vault 是一个给自己和受邀好友使用的资源库。成员可以在同一张书架上搜索漫画、图集、音乐和动画，在电脑上读到一半的漫画，到手机上能接着上次的页内位置读。管理员可以先登记网盘资源，等有人下载时再取回文件。

完整项目使用 Astro、JavaScript、FastAPI、SQLite、Nginx 和 Cloudflare R2。本仓展示其中的阅读同步模块，附有可在本地运行的 HTTP 测试。

## 从一次“继续阅读”请求看实现

1. **读出书架。** API 在同一条 SQLite 查询里关联当前账号的阅读进度和资源资料。原项目在 140 本书的回归场景中，资源表查询由 141 次降至 1 次。
2. **确认页码仍有效。** 同一本漫画重新编排后，第 4 页可能已是另一张图。服务端按图片顺序计算指纹，再决定能否恢复旧进度。未变化的阅读页复用解析结果。
3. **处理两台设备同时写入。** 客户端提交上一次读到的版本号，服务端在写事务中核对版本。晚到的旧写入收到 HTTP 409，保留另一台设备已经保存的位置。

## 本地验证

需要 Python 3.13。测试使用临时 SQLite 库和合成书目，结束后自动清理。

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest -v
```

两项测试分别覆盖 140 本书的排序、查询次数和指纹缓存，以及版本冲突、有效写入和账号间的阅读记录隔离。测试通过 FastAPI TestClient 调用实际路由，账号身份由测试提供。

## 项目中的其他工程实践

| 场景 | 实现与验证 |
| --- | --- |
| 大文件按需分发 | Mac 执行端领取任务、校验来源并分片直传 R2，离线时由服务器接管。原项目线上验证过 990 MiB 文件的 62 片传输及整文件校验。 |
| 视频开播等待 | 在选集阶段提前解析网盘地址，点击播放才请求视频。原项目同机 Chromium 对照 3 集真实片源，在地址已就绪的条件下，平均点击到首帧耗时从 3.52 秒降至 2.59 秒。 |

上表是完整项目的验证记录摘要。本仓可直接复现阅读同步部分。
